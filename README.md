# pdfjig — 治具

**PDF を綴じ、解き、取り出すためのデスクトップユーティリティ。**

[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

---

## 名前について

治具（じぐ、jig）とは、加工物を正確な位置に固定し、**同じ作業を誰がやっても同じ精度で繰り返せる**ようにするための道具である。

pdfjig は PDF に対して同じ役割を果たす。書類を綴じ、解き、中から情報を取り出す作業を、手順と精度を固定したまま繰り返せるようにする。

## 設計思想

1. **確定的処理が主、AI は従。**
   座標・構造の解析は決定的アルゴリズムが行う。AI は意味的な整形を提案するだけで、確定的処理の結果を上書きする権限を持たない。

2. **AI は提案しかしない。**
   分割・リネーム・整形はすべて「提案 → プレビュー → ユーザー承認 → 適用」の 3 段を経る。AI の出力が直接ファイルを変更する経路は存在しない。

3. **AI なしで完全に動く。**
   API キー未設定でも全機能が利用可能でなければならない。AI は増築であって土台ではない。

4. **中身は触らない。**
   ページの並べ替え・抽出・暗号化は行うが、PDF 本文のテキストやベクタ内容は改変しない。

## できること

最新版は **v0.1.0**。下の表の「今」の列が、いま配布しているアプリで実際に使える機能である。

| カテゴリ | 機能 | 今 | 予定 |
|---|---|:---:|:---:|
| ページ操作 | 追加（複数ファイルを 1 つに綴じる）、区切りを指定した分割、削除、並べ替え、回転、範囲抽出 | ✅ | |
| パスワード | パスワード付き文書を開く | ✅ | |
| テキスト抽出 | 全文 / ページ単位 / 座標付き | API のみ | M1 で画面から |
| 表抽出 | lattice・stream 両モード、矩形範囲指定 | | M1 |
| 暗号化 | 設定、解除、判定 | | M1 |
| 出力 | XLSX（既定）/ CSV（BOM 付き UTF-8）/ JSON | | M1 |
| 文書情報 | メタデータ読み書き、ページ数、暗号化状態 | | M1 |
| AI 補助 | 表の正規化、文書境界検出、リネーム・分類、OCR 誤字補正 | | M1 以降 |
| コマンドライン | バッチ / CI 連携 | | M2 |

**v0.1.0 に AI 機能は入っていない。** API キーの設定画面も外部への通信も存在しない。
AI なしで実用に耐えることを確かめてから足す、という順序を履歴に残すためである（設計思想 3）。

暗号化された文書に対するページ操作は今はできない。保護の引き継ぎには元のパスワードが要り、
黙って平文で書き出せば、保護されているつもりで機密文書を配ることになるため。
パスワードを受け取る経路を持つ M1 の暗号化機能とあわせて実装する。

## Non-goals

以下は **要望が来ても実装しない**。これは方針変更の余地がある「未対応機能」ではなく、当初からの設計上の線引きである。

- **PDF 本文のテキスト直接編集** — 設計思想 4 に反する
- **電子署名・タイムスタンプ** — PKI 基盤・証明書チェーン管理が必要になり、製品の性格が変わる
- **フォームの作成** — フォームへの入力・値の読み取りは将来検討の余地があるが、作成は対象外
- **PDF の生成・帳票出力** — 既存の帳票ツールの領域
- **全文 RAG チャット** — 汎用 LLM ツールの領域であり、デスクトップアプリの優位性がない

## 構成

```
pdf-desktop ──┐
              ├──> pdf-ai ──> pdf-core
pdf-cli ──────┘
              └────────────> pdf-core
```

| モジュール | 役割 |
|---|---|
| `pdf-core` | 確定的処理。外部ネットワーク通信を一切行わない |
| `pdf-ai` | LLM プロバイダの抽象化。提案（`Proposal`）を返すのみ |
| `pdf-cli` | バッチ / CI 連携（picocli） |
| `pdf-desktop` | JavaFX UI |

**`pdf-core` は `pdf-ai` に依存しない。** この依存方向は Gradle の依存宣言と ArchUnit テストの双方で強制している。

## 動作環境

- Windows 10 21H2 (x64) 以降 / Windows 11 (x64)
- ランタイムを同梱して配布するため、Java の事前インストールは不要

## インストール

[Releases](https://github.com/propagandist/pdfjig/releases) から取得する。

| ファイル | 用途 |
|---|---|
| `PDFjig-<version>.exe` | **個人で使うならこれ。** ユーザー単位でインストールし、管理者権限が要らない |
| `PDFjig-<version>.msi` | 情報システム部門による一括配布向け。マシン単位で入り、管理者権限が要る |
| `PDFjig-<version>-win-x64.zip` | インストールせずに使う。展開して `PDFjig.exe` を直接実行する |

EXE と MSI は同じ製品であり、両方を同時にインストールすることはできない。
入れ替えるときは先に片方をアンインストールする。

コード署名をしていないため、初回起動時に Windows SmartScreen の警告が出る。
`SHA256SUMS.txt` で取得したファイルのハッシュを確かめられる。

画面とインストーラでの表示名は **PDFjig**、コマンド名とパッケージ名は `pdfjig` である。
コマンドは小文字が自然であり、表示名とは役割が違うため揃えていない。

## 開発

```
./gradlew build
```

ビルドには JDK 21 が必要。JavaFX は Gradle が解決するため、JavaFX 同梱の JDK でなくてよい。

配布物を作る場合は、加えて [WiX Toolset 3.14](https://github.com/wixtoolset/wix3/releases)
を PATH に通しておく（jpackage が要求するのは 3.x であり、v4 では動かない）。

```
./gradlew :pdf-desktop:packageAll -Pversion=0.1.0
```

`dist/` に MSI / EXE / ZIP ができる。リリース時は CI が同じことを行うため、
手元で回す必要があるのは動作を確かめたいときだけである。
