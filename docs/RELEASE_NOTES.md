# PDFjig 0.2.2

**不具合を直した版。** 保存の経路で、**元のファイルを失いうる不具合を 2 つ**直した。
**並べ替えや削除をすると、ページ番号欄の番号が中身とずれていた**のも直した。
「パスワードで保護して保存…」は、ツールバーからも選べるようにした。

**v0.2.1 以前を使っている場合は入れ替えること。** 自動更新の仕組みは無い。

★ **v0.1.2 以前から入れ替えるときは、先に
[v0.2.1 のリリース本文](https://github.com/propagandist/pdfjig/releases/tag/v0.2.1)の
「上から入れても、前の版が消えなかった」を読むこと。** 手順を誤ると、入れた版が起動しなくなる。
**v0.1.2 以前には、失って困るものに届く経路がほかにも 2 つあった**（v0.2.1 で直した）——
共有フォルダでは出力先のフォルダの外を消させられたこと、保存の直後に電源が落ちると新旧どちらも失いうることである。
**入れた後に、インストール済みのアプリの一覧で PDFjig が 1 つだけであることを見ること**
（一覧は「設定」→「アプリ」→「インストールされているアプリ」。Windows 10 では「アプリと機能」）。
**2 つ以上並んでいたら、全部アンインストールしてから 0.2.2 を入れ直す。** 古いほうだけを消してはならない——
新しいほうのファイルも一緒に消え、起動しなくなる。v0.2.1 の本文の「0.2.1 を入れる」は、0.2.2 と読み替えること。

## この版で入ったもの

### 「パスワードで保護して保存…」をツールバーから選べる

**ツールバーの「保存」の隣に「保護」を置いた。** 押すと「パスワードで保護して保存…」と同じ窓が開く。

**メニューの場所も変えた。** v0.2.1 では「ツール」の下にあった。
いまは**「ファイル」の「名前を付けて保存…」の下**にある。どちらも保存の別形なので、同じ場所で選べるようにした。

**保護が引き継がれないことを訊く窓の案内も、これに合わせた。** 守りたいときは、中止して
**ツールバーの「保護」か、メニューの「ファイル」→「パスワードで保護して保存…」**を使うよう案内する。

## この版で直したこと

### ★★ pdfjig を 2 つ起動して同じフォルダへ保存すると、元のファイルを失うことがあった

**上書き保存の途中、元のファイルは作業場所（`.pdfjig-` で始まるフォルダ）へいったん退避する。**
その間にもう一方の窓が同じフォルダへ保存すると、**その作業場所を残り物と見て、退避した元ごと消すことがあった。**
保存の時刻が重なったときだけ起きる。

**別の窓が使っている作業場所には触らない形にした。** 片づける前に、使われていないことを確かめて押さえる。

### ★ 共有フォルダでは、保存の最中に元のファイルを別の場所へ移させられうる形だった

**作業場所は、出力先のフォルダと同じ権限で作られる。** 出力先に書ける人は、
**保存の最中に作業場所をジャンクションへ差し替えられた。** そうされると、**新しい文書は利用者が選んでいない場所へ書かれうるし、
上書き保存なら、退避する元のファイルもそこへ移りうる**（同じドライブのとき）。
保存の最中を狙う必要があるので、上の片づけの件より当たりにくい。
★ **差し替えて実際にファイルが移るところは再現していない。** 保存の最中に作業場所を改名できることを確かめ、その先は JDK の動きから読んだ。

**保存の間、作業場所と、その上のフォルダを改名できないように押さえる形にした。**
押さえられなかったときは、保存を止めて伝える。

★ **共有フォルダ・ネットワークドライブ・他の利用者も書ける場所へ保存しているなら、この版へ入れ替えること。**

★ **防げる範囲**

- Windows のフォルダと Windows の共有で確かめた。**Samba で動く NAS では効かない見込みがある**（確かめていない）
- **保存先のパスの途中にあるジャンクションは押さえられない**
- 出力先に書ける人が、作業場所の中にファイルを置くことは止めない。
  その人が、保存した後のファイルに対して元から持っている権限は越えない

**片づけで消すのは、pdfjig が作業場所に作る 4 つの名前（`output.pdf` ／ `replaced.pdf` ／ `held` ／ `pin`）だけである。**
v0.2.1 の 3 つに、押さえるための `pin` が加わった。

### ★ 並べ替えや削除をすると、ページ番号欄の番号が中身とずれていた

**表紙と目次にローマ数字、本文に算用数字を振った文書で表紙を消すと、目次に `i` が付く形になっていた。**
v0.1.1 からの全版である。**書き出したページには、元の文書で付いていた番号が付くようにした。**
「追加」でほかの文書と綴じたときも同じである。綴じた中に番号の設定を持つ文書があれば、持たない文書から来たページには元のページ番号を算用数字で付ける
（前は、直前の文書の最後の番号の続きになっていた）。
★ **前の版の閲覧ソフトの表示で確かめたのではない。** 書き出す処理を読んで見つけ、書き出したファイルの中身で直ったことを確かめた。

★ **ずれたまま残る文書がある。**
- **ページ番号の設定そのものが読めない文書**は、番号に手を付けずに書き出す
- **ページの木の一部が仕様どおりでない文書**では、まだずれることがある

### 前の保存が途中で終わったという知らせが、成功した保存のあとも出続けた

- **置き換えが済んだのに、退避の印を外し損ねると**、同じフォルダへ保存するたびに
  「前の保存が途中で終わった」と出ていた。**保存は済んでおり、残っていたのは置き換える前の元である**
- **元のファイルを退避する前に落ちると、作業場所が消えずに残り続けた。** 何も知らせないまま残っていた

**印を外し損ねたら、置き換えの済んだ控えのほうを消すようにした。** 印だけが残った作業場所は、
次に同じフォルダへ保存したときに片づける。本当に控えを抱えた作業場所は、今までどおり在り処を伝える。
★ **v0.2.1 までに残った作業場所は、控えを抱えていれば知らせ続ける。** 元のファイルかどうかを見分けられないためである。
開いて確かめてから消すこと（下の「既知の制限」）。

### ほかに直したこと

- **複数のファイルのページを組んで保存すると、細工された PDF で「ファイルの読み書きに失敗しました」と出ていた。**
  読み書きの失敗ではなかった。いまは 1 つのファイルのときと同じく「PDF として読み取れません」と出る
- **入れ子が極端に深い細工された PDF を、ほかの読めない PDF と同じように扱うようにした。** 開くときは
  「PDF として読み取れません」と出る
- **不具合を知らせるための記録（`%LOCALAPPDATA%\pdfjig\logs\`）に、失敗が起きたプログラムの中の位置が残らなくなっていた。**
  v0.1.2 で、パスワードが記録に出ないようにしたときからである。**その位置は残すようにした。**
  パスワードも、文書のパスも、例外のメッセージも書かないことは変わらない

## できること

| 操作 | 内容 |
|---|---|
| 開く | PDF を開いてサムネイル一覧を表示する。パスワード付きの文書も開ける |
| 並べ替え | サムネイルをドラッグして順序を入れ替える |
| 削除 | 選択したページを取り除く |
| 回転 | 右 / 左に 90 度回す |
| 範囲抽出 | 範囲を指定して、その範囲だけ残す |
| やり直し | 並び・向き・区切りを開いた直後の状態に戻す |
| 追加 | 開いている文書に他の PDF のページを足す。足したページはサムネイル上で一緒に並べ替えられる |
| 区切り | 新しいファイルの先頭にするページに印を付ける。枚数で機械的に入れることもできる |
| 分割 | 区切りに従って複数のファイルに分ける |
| 1 枚ずつ | 全ページを 1 ページずつのファイルに分ける。区切りは見ないし、消しもしない |
| 保存 | 並べ替え・削除・回転をまとめて 1 つのファイルに書き出す |
| **保護して保存** | **パスワードと権限を掛けて書き出す。** ツールバーの「保護」か、「ファイル」→「パスワードで保護して保存…」 |
| バージョン情報 | ヘルプメニューから版数・実行環境・AI の有無を確認する。不具合の報告に貼れる形でコピーできる。**更新の確認もここから** |

**パスワード付きの文書にも、上の操作がすべて使える。** 書き出すたびにパスワードを訊く。

並べ替え・削除・回転・追加はファイルを直接書き換えない。画面上の並びを変えるだけで、
「名前を付けて保存」で初めて書き出す。**勝手に上書きされることはない**——
★ **開いているファイルそのものを保存先に選べば置き換わる。**
そのときは Windows の保存ダイアログが「置き換えますか？」と訊く。

複数の PDF を 1 つに綴じるときは、1 つを開いてから「追加」で他を足す。足したページは
元からあったページと区別なく並べ替え・回転・削除でき、最後に一度だけ保存する。
どのページがどのファイルのものかは、一覧の色とサムネイルの帯で分かる。
間違えて足したファイルは、一覧の「×」か「ツール」→「ファイルを外す」で外せる。

逆に 1 つの文書を分けるときは、**新しいファイルの先頭にしたいページを選んで「区切り」を押す。**
サムネイルの左に縦線が出て、そこから次のファイルが始まる。印を付け終えてから「分割」を押す。
スキャンした束は書類ごとに枚数がまちまちなので、枚数で均等に割る方式では当たらない。
定型の綴りなら「N ページごとに区切る」で機械的に入れられる。
全部バラすだけなら「1 枚ずつ」で足りる。こちらは区切りを見ないので、付けた印はそのまま残る。

## この版に入っていないもの

以下は実装済みではない。README の機能表に挙がっていても、この版のアプリからは使えない。

- **しおり・文書情報・ページラベルの編集**（v0.3.0 予定）
- **表抽出**（v0.4.0 予定）
- **XLSX / CSV / JSON 出力**（v0.4.0 予定）
- **テキスト抽出の画面**（いまは `pdf-core` の API としてだけ動く。v0.4.0 予定）
- **AI 機能一式**（v0.5.0 以降）
- **コマンドラインツール**（配布物にはデスクトップアプリのみが入る）

以下は要望が来ても実装しない（設計上の線引き）。

PDF 本文のテキスト直接編集 / 電子署名 / フォーム作成 / PDF 生成・帳票出力 / 全文 RAG チャット

**上書きを避けるための小細工もしない。** 同名を見つけて `foo(1).pdf` のように連番を振ることも、
元のファイルを `.bak` に退避することもない。**どちらも「消えていないはず」という期待を作る割に、
どこに何が残ったのかが利用者から見えなくなる。** 上書きするかどうかは、その場で利用者が決める。

## 既知の制限

- **EXE を入れると、アンインストール情報のキーがマシン単位の場所に作られる**（Windows Installer の登録の仕方で、
  こちらの作り方を直して変わるものではなかった。v0.1.2 では「次の版で直す」と書いた）。
  **ほかの利用者のコントロールパネルの「プログラムと機能」には並ばなかった**——管理者が入れた場合も、
  標準ユーザーが入れた場合も同じだった（Windows Sandbox で確かめた）。
  ★ **v0.1.2 で書いた、設定アプリの一覧（「インストールされているアプリ」／「アプリと機能」）に並ぶかは未確認である。** 共有する機械では、
  **消すときは入れた本人が消すこと**
- **上書きの扱いが「保存」と「分割」で違う。** どちらも上書きの判断は利用者のものだが、
  確認を取る場所が違う。
  - **「名前を付けて保存」は置き換える。** 既存のファイルを選ぶと、Windows の保存ダイアログが
    「置き換えますか？」と訊く。**確認を出すのはこのダイアログであり、pdfjig ではない。**
    「はい」と答えると置き換わる
  - **読み取り専用のファイルへは書き出さない。** 失敗として出て、元のファイルは属性も中身も変わらない
  - **分割は 1 つも書かずに失敗する。** 出力先に同名のファイルが 1 つでもあると、
    その時点で止まる。複数のファイルを一度に作る操作であり、
    どれが置き換わるのかを 1 つずつ確認させる形にはしていない
- ★ **アプリごと落ちたときは、その場では何も伝えられない。**
  **電源断・タスクの強制終了と、Windows のログオフ・シャットダウン**がそれに当たる。
  **閉じる前の確認もここは通らない。**
  - **次に同じフォルダへ保存したとき、控えの在り処を伝える。**
    ★ **分割では伝えない**——分割は作業場所を使わないので、見に行かない
  - **出力先が空で、同じフォルダに `.pdfjig-` で始まる作業場所が残っていたら、
    その中の `replaced.pdf` が元のファイルである。**
    **`output.pdf` は書きかけの新しいほうで、取り違えると保存前の内容を失う。**
    **消す前に開いて確かめること**
  - ★★ **パスワード付きの文書から、保護を掛けずに（またはユーザーパスワードを空にして）書き出していた場合、
    `output.pdf` は誰でも開ける。**
    要るものを取り出したら、**そのフォルダごと消すこと**
- ★ **書き出しの最中に「終了」を押すと、書き終わるまで待ってから閉じる。** その理由は状態行に出るが、
  **読み上げには届かない**
- **EXE をアンインストールすると、設定とログも消える**（#254）。
  設定はファイルを選ぶダイアログが始めるフォルダ 2 つだけで、消えても次の起動が既定に戻るだけである。
  ★ **不具合を知らせてもらうときは、アンインストールする前に `%LOCALAPPDATA%\pdfjig\logs\` を写しておくこと**
- **コード署名をしていない。** 初回起動時に Windows SmartScreen の警告が出る。
  「詳細情報」→「実行」で進める。下のチェックサムで取得したファイルを確かめられる

## 動作環境

- Windows 10 21H2 (x64) 以降 / Windows 11 (x64)
- Java の事前インストールは不要（ランタイムを同梱している）

## どれを取得すればよいか

| ファイル | 用途 |
|---|---|
| `PDFjig-0.2.2.exe` | **個人で使うならこれ。** ユーザー単位でインストールし、管理者権限が要らない |
| `PDFjig-0.2.2.msi` | 情報システム部門による一括配布向け。マシン単位で入り、管理者権限が要る |
| `PDFjig-0.2.2-win-x64.zip` | インストールせずに使う。展開して `PDFjig.exe` を直接実行する |

EXE と MSI は同じ製品であり、**両方を同時にインストールすることはできない。**
入れ替えるときは先に片方をアンインストールする。

`SHA256SUMS.txt` で取得したファイルのハッシュを確認できる。

```powershell
Get-FileHash .\PDFjig-0.2.2.exe -Algorithm SHA256
```

不具合は Issue へ。**脆弱性は公開の Issue に書かないこと**
（[セキュリティポリシー](https://github.com/propagandist/pdfjig/security/policy)）。
